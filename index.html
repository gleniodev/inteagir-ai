01 / Preparação

Documentação sem burocracia

Antes de abrir a ferramenta de IA, a equipe precisa saber o que vai construir. Não é necessário escrever uma documentação enorme: estes cinco arquivos já orientam bem o projeto.

01ESCOPO.md

Visão e limites

Problema, público, resultado esperado, funcionalidades obrigatórias e o que fica fora da primeira versão.

02TELAS_E_FLUXOS.md

Interfaces e jornadas

Quais telas existem, como navegar e o que professor, aluno, responsável e psicólogo conseguem fazer.

03REGRAS_DA_IA.md

Adaptação com IA

Entradas, exemplos, estrutura da resposta, regras de acessibilidade e limites do conteúdo gerado.

04BACKLOG.md

Tarefas e critérios

Tarefas em ordem de prioridade, responsável por cada entrega e como saber que está realmente pronta.

05AGENTS.md

Combinados da IA programadora

Instruções permanentes para não inventar recursos, manter a stack simples, respeitar o escopo e explicar o que mudou. Em ferramentas que não usam AGENTS.md, adapte essas regras ao formato suportado.

Regra: documento curto e atualizado vale mais do que um documento perfeito que ninguém consulta.

03 / Roteiro de desenvolvimento

Seis etapas. Sem atropelar.

A IA deve receber uma tarefa de cada vez. A equipe só avança quando o resultado atual está testado e funcionando.

ETAPA 01

Preparar projeto

Escolher stack, repositório, documentos e página inicial.

ETAPA 02

Montar telas

Criar interfaces responsivas com dados de exemplo.

ETAPA 03

Fluxo principal

Professor cria e aluno responde uma atividade fixa.

ETAPA 04

Integrar a IA

Substituir conteúdo fixo por resposta estruturada da IA.

ETAPA 05

Outros perfis

Conectar responsável e psicólogo aos dados do exemplo.

ETAPA 06

Publicar e testar

PWA, revisão, celular, apresentação e plano B.

Ciclo de cada tarefa: pedir → implementar → testar → revisar → salvar.

Não aceite “pronto” só porque a IA disse que terminou. Abra a funcionalidade, clique, teste os erros e só então marque a tarefa como concluída.

04 / Primeiros passos

GitHub do Zero

Nunca usou GitHub? Aprenda os seis conceitos essenciais e faça sua primeira contribuição usando o GitHub Desktop, sem precisar decorar comandos de terminal.

▤

Repositório

A pasta compartilhada do projeto na internet. O nosso é gleniodev/inteagir-ai.

⑂

Branch

Uma linha de trabalho separada para desenvolver sem alterar a main.

●

Commit

Um registro das mudanças, com uma mensagem dizendo o que foi feito.

↑

Push

Envia seus commits ao GitHub. Publish branch envia uma branch pela primeira vez.

↗

Pull Request (PR)

Um pedido para a equipe revisar o trabalho antes de integrar.

⇄

Merge

Junta o trabalho aprovado à main, nossa versão principal.

Seu primeiro Pull Request, passo a passo

Abra o GitHub Desktop e faça uma etapa por vez. Os nomes dos botões aparecem em inglês em várias versões.

  1. Prepare seu acesso

    Crie ou entre na conta em github.com, instale o GitHub Desktop e faça login. O mentor precisa dar permissão de colaborador. Sem ela, peça ajuda para trabalhar com um fork.

  2. Clone o repositório

    Abra gleniodev/inteagir-ai, clique em Code → Open with GitHub Desktop → Clone. Clonar significa trazer uma cópia para seu computador.

  3. Crie sua branch

    No Desktop, comece na main atualizada. Se houver mudanças remotas, use Fetch origin → Pull origin. Depois clique em Current Branch → New Branch e nomeie treino/seu-apelido.

  4. Altere um arquivo simples

    No editor, crie treino/seu-apelido.md, escreva uma frase sobre o projeto e salve. Não altere o index.html neste exercício.

  5. Registre um commit

    Volte ao Desktop, confira a aba Changes e digite no Summary algo como docs: primeira contribuição. Clique em Commit to treino/seu-apelido.

  6. Envie sua branch

    Clique em Publish branch para enviar a nova branch ao GitHub. Depois, use Push origin quando tiver novos commits. A main ainda não mudou.

  7. Abra um Pull Request

    No Desktop, use Preview Pull Request → Create Pull Request, ou abra a branch no GitHub. Confira base: main, descreva o que fez e crie o PR.

  8. Peça revisão e acompanhe o merge

    Compartilhe o link do PR. Outro colega testa e o mentor aprova ou pede ajustes. Após o merge, volte à main no Desktop e use Fetch origin → Pull origin para atualizar.

Se aparecer erro de permissão, conflito ou pedido para sobrescrever arquivos, não force: chame o mentor. Cada dupla deve usar um apelido de branch diferente.

Ferramentas mínimas

Um repositório no GitHub, GitHub Desktop (opcional para evitar terminal), uma ferramenta de IA para código e um projeto na Vercel. Só isso para começar.

Acordo contra conflitos

Uma tarefa por pessoa/dupla, uma branch por tarefa. Arquivos compartilhados e mudanças grandes passam antes pelo mentor.

Prompt-base para uma tarefa da equipe
Leia ESCOPO.md, TELAS_E_FLUXOS.md, REGRAS_DA_IA.md e AGENTS.md.

Tarefa: [descrever UMA funcionalidade pequena].
Resultado esperado: [como vou testar e saber que funciona].

Regras:
- Não implemente funcionalidades adicionais.
- Não altere arquivos de outras tarefas sem avisar.
- Preserve a acessibilidade e a interface existente.
- Não exponha chaves nem use dados reais de crianças.
- Ao finalizar, liste os arquivos alterados e como testar.
- Se encontrar ambiguidade, explique a decisão tomada.
Cada dupla substitui os campos entre colchetes e executa apenas a própria tarefa.
Se a equipe for pequena, uma pessoa pode assumir mais de um papel. O importante é evitar que duas pessoas modifiquem a mesma tela ao mesmo tempo. Reunião rápida: 10 minutos para dizer o que fez, o que fará e onde está travada.
06 / Inteligência artificial

A IA cria o conteúdo. O app cria a tela.

Em vez de executar qualquer HTML ou JavaScript produzido pela IA, peça conteúdo estruturado, como enunciado, opções e resposta. Seu próprio template HTML transforma isso em uma atividade interativa mais previsível.

Adaptação não é padrão único.

Preferências sensoriais e cognitivas variam entre estudantes com TEA. Ofereça interface previsível, instruções claras e opções ajustáveis. O professor revisa o que a IA produzir antes da aplicação.
